## 3. SDLS as the standard answer, and what small satellites do instead

What the standard says ([CCSDS 355.0-B-2, July 2022](https://public.ccsds.org/Pubs/355x0b2.pdf)):

- It applies authentication and/or confidentiality to the data field of TM, TC, AOS and USLP transfer frames, at the data link layer only (sec. 2.1). Issue 2 added USLP support and a normative reference to the Extended Procedures book, [CCSDS 355.1-B-1](https://public.ccsds.org/Pubs/355x1b1.pdf), which handles key management, SA management and monitoring.
- A Security Association is "a simplex (one-way), stateful cryptographic session for providing authentication, data integrity, replay protection, and/or data confidentiality" (sec. 2.3.1.1). Every protected frame carries a Security Header (SPI, IV, anti-replay sequence number, pad length) and a Security Trailer (MAC) (sec. 2.3.1.4).
- Authentication: a MAC over selected header fields plus the frame data (sec. 2.3.2.2).
- Replay protection (sec. 2.3.2.3): the sender increments a sequence number once per frame; the receiver accepts a frame only if the number is higher than the stored value and within a fixed positive "Sequence Number Window" set in the SA, and then stores the new value. Frames outside the window are discarded. Rollover handling is mission-specific.
- Note in sec. 2.3.3: "Encryption used without authentication can provide a false sense of security."

SDLS provides background for future counter and authorization work. The Platform’s teaching counter is not an SDLS implementation or compliance claim; the [packet format](../specs/packet-format-v1.md#command-body) reserves authorization fields without selecting a scheme. NASA’s [CryptoLib](https://github.com/nasa/CryptoLib) is a reference implementation for cFS.

What small satellites actually do (primary evidence):

- [Space Odyssey (IEEE S&P 2023)](https://jwillbold.com/paper/willbold2023spaceodyssey.pdf): two of three analysed satellites had no TC authentication or encryption at all; of 17 surveyed satellites only 9 reported any anti-takeover measure, with "protocol obscurity" as common as encryption and only 5 using on-board access control. Authors: "most small non-constellation LEO satellites have no TC protection". Survey also found 7 of 13 respondents use a custom protocol rather than a standard one, and small satellites lean custom.
- [libcsp](https://github.com/libcsp/libcsp), the stack OPS-SAT and many GomSpace-based CubeSats use, offers an optional truncated 4-byte HMAC ([csp_hmac.h](https://raw.githubusercontent.com/libcsp/libcsp/develop/include/csp/crypto/csp_hmac.h)); there is no SDLS-style sequence window in the core API. Space Odyssey notes the unprotected COM on OPS-SAT exposed "the libCSP default handlers (i.e., ping replies, uptime checks, and reboots)".
- Amateur-band CubeSat downlinks use AX.25/AFSK or GMSK with no authentication by design; the HTB track's "Signal from Space" challenge and PwnSat's AX.25/AFSK1200 telemetry both rely on this ([HTB blog](https://www.hackthebox.com/blog/hack-the-orbit-satellite-exploitation-track), [pwnsat.org](https://pwnsat.org/docs/get-started/introduction/)).
- NASA's BPG (Rev B, MI-AUTH-01) recognises the gap: it asks for encryption "in addition to some form of authentication (e.g., Galois/Counter Mode GCM)" and says the vehicle must protect itself even if the ground is compromised.
